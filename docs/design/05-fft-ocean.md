# 05 · FFT 海面（Tessendorf 光谱法）设计

> 状态：设计评审稿（2026-10-08），未实施。触发条件：试玩后认为 Gerstner 浪形不够真实。

## 1. 动机：Gerstner 的现状瓶颈

当前海面是 4 个 Gerstner 波分量的叠加（`wave_provider.gd` WIND_TABLE）：

- **波形重复感**：4 个正弦分量，长时间注视可辨认出干涉图样；真实海面是数百个波分量的连续谱
- **波峰形状单一**：Gerstner 的尖峰由 steepness 参数统一控制，所有浪峰"尖得一样"；真实海面大浪浑圆、小浪尖锐、破碎处卷边
- **白沫判据是近似的**：现在用坡度（`1 - n.y`）推断破碎，物理上白沫来自波面翻卷（位移场 Jacobian 变负）——FFT 方案可以直接算出 Jacobian，白沫位置精确
- **涌浪与风浪的关系是手调的**：涌浪目前是对最大波分量的改写；谱方法里风浪谱+涌浪谱是两个独立谱峰叠加，物理上更自然

## 2. 核心理论（Tessendorf 2001）

### 2.1 高度场

海面高度是傅里叶级数：

```
h(x, t) = Σ_k h̃(k, t) · exp(i·k·x)
```

其中波矢 k 覆盖 N×N 网格，振幅由**波谱**给出：

```
h̃(k, t) = h̃₀(k)·exp(+iωt) + h̃₀*(-k)·exp(-iωt)   # 共轭对称保证实数结果
h̃₀(k) = (ξr + i·ξi) · √P(k) / √2                 # ξ 为高斯随机数（固定 seed）
ω(k) = √(g·|k|)                                   # 深水色散关系（与现有 Wave 一致）
```

### 2.2 波谱：Phillips + JONSWAP 修正 + 方向扩展

```
Phillips:  P(k) = A · exp(-1/(kL)²) / k⁴ · |k̂·ŵ|²     # L = U²/g，U 为风速
JONSWAP:   P ×= γ^r，r = exp(-(√(k/kp) - 1)² / 2σ²)   # 谱峰增强，γ=3.3
方向扩展:  |k̂·ŵ|² → cos²s 扩展（s 随波数增大，短波方向更散）
小波阻尼:  P ×= exp(-k²·l²)，l ≈ 0.5m，抑制 capillary 波
```

**风速输入是连续的**：U = `beaufort_to_kn(wind_level) × 0.514` m/s → 谱随蒲福级连续变形，天然兼容现有 `WIND_TABLE` 的连续插值语义，替换后 `set_wind()` 接口不变。

### 2.3 位移与法线（choppiness）

```
水平位移: D(x, t) = -i · Σ_k (k/|k|) · h̃(k,t) · exp(i·k·x)   # 波峰前移 → 尖峰
法线:     N = (-∂h/∂x, 1, -∂h/∂z)                             # 另做两个 IFFT，或从高度图差分
```

### 2.4 Jacobian 白沫判据（本方案最大的画质红利）

位移场的 Jacobian 行列式 J(x,t) < 0 处波面自交 = 物理上的翻卷破碎：

```
J = (1 + λ·∂Dx/∂x)(1 + λ·∂Dz/∂z) - λ²·∂Dx/∂z·∂Dz/∂x
foam = clamp(−J, 0, ∞) 的映射
```

取代现在的坡度+噪声纹理白沫：泡沫精确出现在即将破碎的波峰上，且自带"破碎后残留"的实现空间（J 场时间衰减积分）。

## 3. 架构：WaveProvider 接口不变，换后端

```
┌─────────────────── WaveProvider（接口不变）───────────────────┐
│ set_wind(蒲福级) / set_swell(0..1) / get_height(x,z)          │
│ get_shader_params() / current_intensity() / time              │
└──────────────┬───────────────────────────────┬───────────────┘
        现在：Gerstner 4波                M4：SpectrumField（新增）
        WIND_TABLE 插值                   连续风速 U → 双谱叠加 → IFFT
```

**关键约束（也是本设计的主要难点）**：CPU 浮力物理需要逐帧 `get_height()`，而 FFT 天然是"整块网格一次算出"。三个方案对比：

| 方案 | 做法 | 优点 | 缺点 |
|------|------|------|------|
| **A. GPU compute + 回读** | RD 计算着色器出图，异步回读船周围小块 | 分辨率可以很高 | 回读延迟 1~2 帧（物理用旧数据，浪大时有误差）；RD API 复杂 |
| **B. CPU FFT（推荐）** | C#（mono 运行时已有）算 128×128 IFFT，同时上传纹理给 GPU、CPU 侧双线性插值供浮力 | 物理/视觉天然一致；延迟为零；调试简单 | 分辨率受限（128² ≈ 每分量 2×128²·log₂128 ≈ 23 万次复数蝶形，C# 约 1~2ms） |
| **C. 混合** | Gerstner 大波保物理 + FFT 只出细节法线 | 改动最小 | 视觉浪≠物理浪，违背项目第一约定，白沫 Jacobian 与大波脱节 |

**推荐 B**。128×128 网格覆盖 200m 波长域（分辨率 1.56m），配合：

- **双频谱叠加**：风浪谱（峰波长随风速 10~120m）+ 涌浪谱（固定 200m 长峰，`set_swell` 控制增益）——涌浪从"改写最大波"升级为独立谱峰
- **周期化平铺**：FFT 输出天然周期，200m 域平铺；重复感用第二层 1.5km 低频图（64×64）调制振幅遮蔽
- **每 2 帧更新一次** IFFT（30Hz 波形演化足够），物理插值中间帧；预算降到 ~0.5ms/帧
- **回退开关**：`WaveProvider.backend = "gerstner" | "fft"`，随时切回

### 输出纹理（每 2 帧上传到 GPU）

| 纹理 | 内容 | 用途 |
|------|------|------|
| displacement RGBA16F | (Dx, Dy, Dz, J) | 顶点位移 + Jacobian 白沫 |
| normal RGBA16F | 由 Dy 差分 | fragment 光照（替换解析法线） |

### ocean.gdshader 改动

- vertex：`VERTEX += texture(displacement, world_xz / 200m).rgb × 距离淡出`（淡出逻辑保留）
- fragment：法线从 normal 纹理采样；白沫判据从坡度改为 `foam = f(J)`（坡度判据保留作远距离 fallback）；白沫噪声纹理仍用于泡沫内部质感
- 涌浪的 200m 波长 ≈ 域尺寸，注意混叠：涌浪谱峰限制在域的 1/2 以内

## 5. 性能预算

| 项 | 成本 |
|----|------|
| 128²×2 IFFT（高度+位移，30Hz） | ~1ms/帧（C#） |
| 纹理上传 2×128²×8B×30Hz | ~7MB/s，可忽略 |
| GPU：2 次纹理采样替换 4 次三角函数 | 更快 |

## 6. 验证计划

1. **统计正确性**：FFT 浪高的标准差 ≈ 有效浪高/4（对标 WIND_TABLE 各档实测值）；波高分布应接近 Rayleigh
2. **物理一致性**：船在 6 级风下浮力平衡回归（同 M1 标准：船体原点稳定在浪面 ±0.05m）
3. **截图对比**：Gerstner vs FFT 同海况三连拍（平静/中等/风暴），重点看波峰形状多样性与白沫位置
4. **性能**：C# FFT 耗时打印，确认 <2ms
5. **无头回归**：现有全部 `_`*_test 脚本通过

## 7. 风险与对策

| 风险 | 对策 |
|------|------|
| C# 与 GDScript 互操作的开销/复杂度 | FFT 类纯 C# 静态类，GDScript 只传 float 数组；先做单帧耗时 spike 验证 |
| 平铺重复感 | 双层频率 + 大尺度振幅调制图；仍不行再加域旋转双层采样 |
| 128² 对 9m 以下小波欠采样 | 保留现有的逐像素小波法线（小波本来就不进位移） |
|  Jacobian 白沫太"干净" | 与现有噪声纹理相乘，保留手工质感 |
